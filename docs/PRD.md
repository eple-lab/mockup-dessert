# PRD — 달콤공방 수제 디저트 쇼핑몰

> 작성일: 2026-10-29 · 상태: 목업 구현 완료 · 선택 근거: [선택-근거.md](./선택-근거.md)

## 1. 서비스 목적

| 항목 | 내용 |
|---|---|
| 누구를 위해 | 선물할 디저트를 찾는 사람 |
| 어떤 문제 | 어떤 디저트가 있는지, 가격과 판매 여부를 한눈에 비교하기 어렵다 |
| 해결 방법 | 분류별로 상품을 둘러보고, 상세 화면에서 설명·가격·품절 여부를 확인한다 |
| 운영자 기능 | 가게 운영자가 상품을 등록·수정·삭제해 목록을 관리한다 |

## 2. 핵심 화면과 이동 흐름

| 화면 | 주소 | 역할 |
|---|---|---|
| 메인 | `/` | 상품 카드 목록, 분류 필터, 결과 수 |
| 상세 | `/products/[id]` | 큰 이미지, 설명, 가격, 판매 상태, 등록일·수정일, 수정·삭제 버튼 |
| 등록 | `/products/new` | 상품 입력 폼 |
| 수정 | `/products/[id]/edit` | 기존 값이 채워진 같은 입력 폼 |
| 없는 페이지 | 그 외 | "찾으시는 디저트가 없어요" 안내 |

```
메인 ──카드 클릭──▶ 상세 ──수정──▶ 수정 ──저장──▶ 상세
  │                  └──삭제(확인창)──▶ 메인
  └──+ 상품 등록──▶ 등록 ──저장──▶ 새 상품 상세
```

삭제는 별도 화면을 두지 않고 상세 화면에서 확인창을 거쳐 처리한다.

## 3. 요구사항

### 손님 (둘러보기)

| # | 사용자가 할 수 있어야 하는 일 | 확인할 조건 |
|---|---|---|
| U1 | 상품 목록을 본다 | 카드마다 이름, 원 단위 가격(예: 32,000원), 분류, 이미지가 보인다 |
| U2 | 품절 상품을 구분한다 | `soldOut: true`인 상품에 '품절' 표시, 이미지는 흐리게, 가격은 취소선 |
| U3 | 이미지가 없는 상품도 본다 | `image`가 빈 문자열이거나 파일을 못 불러오면 '이미지 없음'. 카드 크기는 다른 카드와 같다 |
| U4 | 긴 상품명도 읽는다 | 카드에서는 두 줄까지 보이고 말줄임, 상세에서는 전체가 보인다 |
| U5 | 분류로 걸러 본다 | 필터를 바꾸면 카드 목록과 "N개의 디저트" 결과 수가 함께 바뀐다 |
| U6 | 상품이 없을 때 안내를 본다 | 전체가 비면 "등록된 상품이 없습니다.", 분류에 상품이 없으면 분류 안내 |
| U7 | 상세 정보를 본다 | 설명, 판매 상태, 등록일, 수정일이 보인다 |

### 운영자 (관리하기, 로컬 실행에서만)

| # | 사용자가 할 수 있어야 하는 일 | 확인할 조건 |
|---|---|---|
| A1 | 상품을 등록한다 | 저장하면 `data/products.json`에 추가되고, 새 상품의 상세 화면으로 이동한다 |
| A2 | 상품을 수정한다 | 수정한 값이 저장되고, 등록일은 그대로, 수정일만 바뀐다 |
| A3 | 상품을 삭제한다 | 확인창에서 승인해야 삭제되고, 메인 목록에서 사라진다 |
| A4 | 잘못된 값을 막는다 | 빈 이름, 정수가 아닌 가격, 분류 미선택 등은 입력칸 아래에 안내하고 저장하지 않는다 |

### 입력값 규칙

| 필드 | 규칙 |
|---|---|
| 상품명 | 필수, 60자 이하 |
| 가격 | 필수, 0 ~ 1,000,000원 정수 |
| 분류 | 필수, 케이크 · 구움과자 · 마카롱 · 쿠키 · 타르트 중 하나 |
| 이미지 경로 | 선택, 비우거나 `/`로 시작하는 public 기준 경로 |
| 설명 | 선택, 500자 이하 |
| 품절 | 체크박스 (불리언) |

같은 규칙을 화면(`src/lib/validate.ts`)과 API가 함께 사용한다.

## 4. 데이터

상품 데이터는 `data/products.json`에 JSON 배열로 둔다. 강의의 6개 필드에 상세 화면과 관리를 위한 3개 필드를 더했다.

| 필드 | 자료형 | 출처 |
|---|---|---|
| `id` | 숫자 | 강의 기본 필드, 등록 시 자동 |
| `name` | 문자열 | 강의 기본 필드 |
| `price` | 숫자 (원) | 강의 기본 필드 |
| `category` | 문자열 | 강의 기본 필드 |
| `image` | 문자열 | 강의 기본 필드 |
| `soldOut` | 불리언 | 강의 기본 필드 |
| `description` | 문자열 | 추가: 상세 화면 설명 |
| `createdAt` | ISO 8601 문자열 | 추가: 등록일, 자동 |
| `updatedAt` | ISO 8601 문자열 | 추가: 수정일, 자동 |

## 5. 이번 구현 범위

### 목업 데이터로 구현한 것

- 위 4개 화면과 404 화면
- 분류 필터, 품절·이미지 없음·빈 목록·긴 상품명 처리
- 등록·수정·삭제: `/api/products` 목업 API가 `data/products.json` 파일을 직접 읽고 쓴다
  - `GET /api/products`, `POST /api/products`
  - `GET · PUT · DELETE /api/products/:id`
  - 잘못된 입력은 400, 없는 상품은 404
- GitHub Pages 배포: 보기 전용 (목록·필터·상세만, 빌드 시점의 데이터)

### 나중에 백엔드가 필요한 것

| 기능 | 필요한 것 |
|---|---|
| 배포된 사이트에서 상품 관리 | 서버와 데이터베이스 (파일 쓰기는 로컬 전용) |
| 운영자만 관리하기 | 로그인과 권한 확인 (지금은 누구나 등록·삭제 가능) |
| 장바구니·주문·결제 | 주문 저장, 결제 연동 |
| 재고 관리 | 재고 수량 필드와 주문 시 차감 처리 |
| 상품 사진 업로드 | 파일 저장소 (지금은 `public/images` 경로만 입력) |

## 6. 범위 밖 (이번에 만들지 않음)

백엔드 서버, 데이터베이스, 로그인, 주문, 결제, 이미지 업로드, 검색 노출 검증.
